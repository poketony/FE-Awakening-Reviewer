# FE Awakening Reviewer

`poketony/FE-Awakening`의 **파이어 엠블렘 각성 지원회화**를 휴대폰에서 읽고 교정한 뒤, 수정 파일을 새 브랜치와 Pull Request로 안전하게 반영하기 위한 개인용 PWA입니다.

## 주요 기능

- 본편 `Awakening/Messages (J)` ↔ `Awakening/Messages (K)` 자동 페어링
- 각성 지원 DLC 22/23/24 J/K 파일 자동 페어링
- C/B/A/S 또는 DLC 회화 단위 버튼 이동
- 일본어 인게임 렌더링 + 해당 장면 원문 대사
- 한국어 인게임 렌더링 + 해당 장면 안전 편집
- 일본어/한국어 장면 번호 동기화
- 화자·표정·음성·페이지·분기 등 제어코드 잠금
- 게임 줄바꿈은 편집창에서 실제 줄바꿈처럼 보이되 저장 시 원래 `\n`으로 복원
- 제어코드/줄바꿈 구조가 달라지면 저장 차단
- 로컬 초안 누적
- C/B/A/S 등 단계별 검수 완료 체크
- 파일별 `미완료 / 진행 중 / 검수 완료` 상태
- **검수 완료 파일 / 전체 파일 기준 진행률**과 보조 단계 진행률
- 원격 `main` 충돌 여부를 PR 생성 직전 재검증
- 수정 파일을 새 `mobile-review/...` 브랜치의 한 커밋으로 생성
- Pull Request 자동 생성
- PWA 설치 가능

## 보안 구조

- GitHub 토큰은 소스 코드에 저장하지 않습니다.
- 입력한 토큰은 `localStorage`, `sessionStorage`, IndexedDB에 저장하지 않고 **현재 페이지의 JS 메모리에만** 둡니다.
- 브라우저에 영구 저장되는 것은 대사 초안과 검수 진행 기록입니다.
- `main`에 직접 커밋하지 않습니다.
- 매번 새 `mobile-review/...` 브랜치를 만들고 PR을 생성합니다.
- PR 생성 직전에 각 수정 파일의 원격 blob SHA를 다시 확인합니다. 검수 도중 같은 파일이 `main`에서 바뀌었다면 쓰기를 중단합니다.

## Fine-grained PAT 만들기

GitHub에서 다음 순서로 이동합니다.

`프로필 사진 → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token`

권장 설정:

- **Token name**: `FE-Awakening-Reviewer`
- **Expiration**: 30~90일 권장. 필요할 때 새로 발급하는 편이 안전합니다.
- **Resource owner**: `poketony`
- **Repository access**: `Only select repositories`
- 선택 저장소: **`FE-Awakening` 하나만**

`Repository permissions`에서는 다음만 변경합니다.

- **Contents: Read and write**
- **Pull requests: Read and write**
- **Metadata: Read-only** — GitHub에서 기본으로 필요한 읽기 권한

`Actions`, `Administration`, `Workflows`, `Pages`, `Secrets` 등의 추가 쓰기 권한은 필요하지 않습니다.

`Generate token`을 누른 뒤 표시되는 토큰은 다시 확인하기 어려울 수 있으므로 안전한 비밀번호 관리자 등에 보관합니다. 토큰을 GitHub 저장소 파일, 메모용 txt, 스크린샷 등에 넣지 마세요.

## 휴대폰에서 처음 연결하기

1. GitHub Pages의 Reviewer를 열고 필요하면 홈 화면에 PWA로 설치합니다.
2. 평소 검수만 할 때는 토큰 없이도 사용할 수 있습니다.
3. 쓰기 기능을 확인하려면 상단 `Fine-grained PAT` 칸에 토큰을 붙여넣습니다.
4. **`쓰기 연결`**을 누릅니다.
5. 상단 상태에 GitHub 계정/저장소 연결 성공 표시가 나오면 준비 완료입니다.
6. 앱을 완전히 종료하거나 페이지가 새로 로드되면 토큰은 메모리에서 사라지므로 필요할 때 다시 붙여넣습니다.

## 실제 검수 순서

1. **본편 / DLC**를 선택합니다.
2. 검색창 또는 회화 선택 메뉴에서 검수할 지원회화를 고릅니다.
3. 파일 위의 **C / B / A / S** 또는 DLC 회화 버튼을 고릅니다.
4. 위쪽 **일본어 렌더링과 원문 대사**를 확인합니다.
5. 아래쪽 **한국어 렌더링과 편집창**을 확인합니다.
6. 한 MID에 장면이 여러 개면 한국어 렌더링 아래의 **이전 / 다음**으로 넘깁니다. 일본어도 같은 장면 번호로 함께 이동합니다.
7. 수정이 필요하면 한국어 대사만 고칩니다. 렌더링은 수정 내용에 맞춰 갱신됩니다.
8. 게임의 기존 줄바꿈은 편집창 안의 실제 줄바꿈으로 표시됩니다. 기존 줄바꿈 위치는 유지하세요. 임의로 추가/삭제하면 구조 검증이 저장을 막습니다.
9. `구조 잠금 정상`을 확인합니다.
10. 수정했다면 **`현재 수정 저장`**으로 로컬 초안에 저장합니다. 장면/단계를 이동할 때도 유효한 수정은 자동 보존됩니다.
11. 해당 C/B/A/S 전체를 눈으로 확인했다면 **`✓ 이 단계 검수 완료`**를 누릅니다. 문장을 수정하지 않았어도 문제가 없음을 확인했다면 완료 처리할 수 있습니다.
12. 모든 단계가 완료된 회화는 파일 자체가 **`✓ 검수 완료`**가 되고 상단 완료 파일 수와 퍼센트가 올라갑니다.

## 진행률 보는 법

큰 퍼센트는 **완전히 검수를 끝낸 파일 수 / 현재 탭의 전체 파일 수**로 계산합니다.

예: `검수 완료 파일 17 / 238`이면 약 `7.1%`입니다.

C/B/A까지 보고 S만 남은 파일처럼 부분 검수 중인 작업도 버려지지 않습니다. 화면 아래의 **단계 기준 진행률**에 별도로 반영됩니다. 따라서 큰 퍼센트는 실제 완결된 파일 수를 보여주고, 보조 퍼센트는 그 안에서 이미 해둔 작업량을 보여줍니다.

검수 완료 기록은 대사 초안과 별개의 로컬 기록입니다. PR을 만들거나 대사 초안을 비워도 완료 체크가 자동 삭제되지는 않습니다.

## 여러 수정사항을 GitHub에 올리기

1. 여러 회화를 검수하면서 필요한 수정들을 로컬 초안으로 쌓습니다.
2. 화면 아래 **`수정 대기`**에서 반영될 파일 수를 확인합니다.
3. 토큰을 아직 연결하지 않았다면 상단에 PAT를 붙여넣고 `쓰기 연결`을 누릅니다.
4. **`커밋 + PR 만들기`**를 누릅니다.
5. Reviewer가 최신 원격 `main`을 다시 확인합니다.
6. 검수 시작 후 같은 원격 파일이 변경된 것이 감지되면 안전을 위해 중단합니다.
7. 문제가 없으면 `mobile-review/YYYYMMDD-HHmm-...` 형식의 새 브랜치를 만듭니다.
8. 모든 수정 파일을 한 커밋으로 묶습니다.
9. `main`을 대상으로 Pull Request를 생성합니다.
10. 표시된 **PR 열기**를 눌러 GitHub에서 최종 diff를 확인합니다.
11. 예상한 한국어 대사만 바뀌었는지 확인한 뒤 PR을 merge합니다.

## 수정이 필요 없는 파일

검수의 목적은 반드시 문장을 바꾸는 것이 아닙니다. 문제가 없는 회화는 아무 수정 없이 `✓ 이 단계 검수 완료`만 누르면 됩니다. 해당 파일에는 GitHub 커밋용 초안이 생기지 않지만, 검수 진행률에는 정상적으로 반영됩니다.

## 특수한 스크립트 수정

이 모바일 편집기는 일반적인 번역/맞춤법/문장 교정을 안전하게 처리하기 위한 도구입니다. 화자, 표정, 음성, 성별 분기, `$k`, `$p`, `$Nu`, `$G` 등 제어코드 자체를 고쳐야 하는 작업은 모바일 안전 편집기의 범위 밖입니다.

그런 경우 `현재 MID 전체 스크립트 확인`으로 구조만 확인하고, 실제 제어코드 수정은 기존 PC 도구를 사용하는 것을 권장합니다.
